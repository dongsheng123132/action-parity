# 提案：把标准的重心搬回「一核多影」，把计分降级为可选审计

> 日期：2026-07-26 · 针对 0.3.0 工作草案
> 状态：提案。未改 `SPEC.md` / `schema/` / `src/validator.mjs`——那几处正在被另一条线修改。

## 问题

**影核已经长成了一个评分标准。**

名字说的是架构：一个权威的动作核心，各平台界面是它的原生影子（`docs/NAMING.md` 里
写得很清楚：「一核多影」）。但正文说的是分数。

词频（全仓 Markdown + 工具链，排除 node_modules）：

| 词 | 次数 |
|---|---|
| `AP-1` / `AP-2` / `AP-3` / `AP-4` | **140** |
| `conformance` | 80 |
| `certification` | 24 |
| `score` / `parity percent` | 35 |
| **`shadow` / `影子`** | **12（其中 10 次在 `NAMING.md`）** |
| `projection` / `投影` | 4 |

`SPEC.md` 里 `shadow` 出现 **0** 次。`MANIFESTO.md` 里 **0** 次。
**「影子」这个概念只活在讨论取名的那份文档里，从没进过规范正文。**

篇幅同样失衡：

| 章节 | 行数 |
|---|---|
| §5 架构不变式（**整个标准的论点**） | 14 |
| §14 符合性等级 | 49 |
| §15 一致性分数 | 43 |

**核心 14 行，记分牌 92 行。**

版本演进也印证了方向：0.2.0「Split declared parity from evidenced parity」、
0.3.0「Score machine access, not manifest completeness」——连续两版的主题都是计分。
cc-switch 试点提的 F1/F2 每一轮都被消化成「把分打得更准」，没有一轮回到
「核和影子的关系该怎么写」。**提反馈的一方（本案例作者）同样在喂这个循环，
两轮回馈通篇在算覆盖率。**

## 根因：英文名本身就是一个度量

- **影核** = 影 + 核。这是对软件**是什么**的判断：只有一个核，界面是它的投影。
- **ActionParity** = action + **parity**。parity 是「等价关系」，是一个**可计算的量**。

一个叫「同等性」的标准，天然会生长出百分比、等级、徽章、认证实验室
（`docs/BUSINESS.md` 里这四样都有）。中英文名编码了两套理论，而英文那套一直在开车。

## 证据：分数与真实工作**反相关**

cc-switch / uu-switch 试点的三阶段实测（见 `CASE-CC-SWITCH.zh-CN.md`）：

| 阶段 | 真实机器可用性 | 当时的分数 |
|---|---|---|
| 原样，零机器入口，Agent 一个动作都调不到 | **无** | 66.7%，通过 AP-2 |
| 加了真 CLI、注册表、16 条无头回归 | **有** | 33.3%，掉到 AP-1 |
| 再加 8 条 GUI 绑定证据 | 更好 | 66.7%，仍 AP-1 |

**什么都不做时分数最好看，真干活时分数先掉下去。** 后两版计分修正正是为了纠正这个，
但这恰恰说明：分数需要不断打补丁才能勉强对齐现实，而它本该指向的那件事——
「是不是一个核、界面是不是影子」——从头到尾没变过，也从来不需要百分比来表达。

两轮之内，同一个人（本案例作者）就发现了两条作弊路径：

1. 把自家 webview 的 IPC 桥声明成机器 Surface，一行代码不写拿满分（0.3.0 已堵）；
2. 某 Surface 证据 0% 时，把它移出必需集合，分数立刻满分（**尚未堵**）。

**有分子分母，就有人优化分子分母。** 这是结构性的，不是再补一个规则能治好的。

## 更要紧的：真正有价值的产出，一个都不来自分数

同一次试点里，实际改善软件的只有三件事：

1. **有了一个机器入口**（`uuctl`）——Agent 从「调不到」变成「调得到」，二元的；
2. **确认闸门从 React 弹窗下沉到动作核心**——修掉一个真实安全缺陷；
3. **清单从手写改成生成物**——让「影子和核对不上」这件事无处藏身。

这三件事**没有一件需要百分比**。它们全部来自架构问题：
「这个动作的唯一实现在哪」「确认在哪一层」「清单和代码谁是真相源」。

分数在整个改造里的贡献是：**零**。它唯一的作用是让人（包括我）花两轮时间讨论
该不该把 `ipc` 降成非必需。

## 提案

### 1. 把 §5 变成正文的中心，并用「一核多影」的语言写

现在的 §5 只有 14 行，且只说了「不许有两份实现」。建议扩写成标准的第一性定义：

- **核（Action Core）**：动作语义与实现的唯一权威所在。
- **影子（Shadow）**：任何界面——GUI、CLI、TUI、MCP、API、测试——都是核的投影。
- **影子里不许有什么**（这是最有操作性的部分，目前散落在 §8/§11 里）：
  - 不许有第二份业务实现；
  - 不许有只存在于该影子里的权限或确认判断（试点抓到的真 bug 就是这一条）；
  - 不许有独立的状态真相源；
  - 不许有只能从这个影子到达的动作。

判据是**二元的**：违反了就是违反了，不需要百分比。

### 2. 等级与计分移出 `SPEC.md`

搬到独立的 `docs/AUDIT-PROFILE.md`，并在开头写明：

> 这是审计一个实现的**一种**做法，不是标准本身。一个实现可以完全符合影核架构
> 而从不产出任何分数。

理由：规范正文应该定义「什么是对的」，审计规程定义「怎么查」。混在一起的后果就是
现在这样——读者（和作者）以为标准就是那四个等级。

### 3. 验证器主输出从「分数 + 等级」改成「违规清单」

```text
# 现在
Declared parity 100%   Evidenced parity 66.7%   Achieved AP-1

# 建议
影子 desktop：8 个动作，0 处自带实现，0 处自带权限判断
影子 cli    ：8 个动作，0 处自带实现，0 处自带权限判断
违规 0 处

未证明 8 处：
  ipc 影子的 8 个动作无法证明落到同一个核（Tauri State 注入，测试构造不出）
```

「未证明」和「违规」分开列，都给具体位置。**没有分子分母，就没有可优化的目标**——
把 Surface 移出必需集合不会让违规清单变短，只会让它多一行「该影子未被检查」。

保留百分比也可以，但降级为审计报告里的附注，不作为主输出、不作为徽章。

### 4. 清单的定位改回「核的公开契约」

现在清单被当成符合性证据（所以要给它打分）。它更该被当成**核对外的接口描述**：
让 Agent 不用读源码就能发现动作、知道输入输出、知道风险和确认要求、然后调用它。

这个用途是二元的：**Agent 能不能靠这份清单把动作跑通。** 能就是能。
试点里 `uuctl list` / `describe` / `run` 能跑通，这件事的价值与 66.7% 无关。

### 5. 词汇回归正文

`一核多影` / `影子` / `投影` 目前只出现在 `NAMING.md`。建议 `SPEC.md` §4 术语表
直接收录「Shadow / 影子」，并在 §5 用它论述。名字里的东西不该只在讲名字时才出现。

## 不建议做的事

- **不建议改名。** `action-parity` 是已发布的 wire identifier，`NAMING.md` 的兼容规则
  不该为了这次调整破掉。要调的是重心，不是招牌。
- **不建议删掉等级。** 等级对「我该做到哪一步」是有用的路标，问题在它占了正文中心。
  搬到审计规程里、并明确「符合架构 ≠ 需要拿等级」即可。
- **不建议现在动 `BUSINESS.md`。** 认证实验室那条商业路径依赖分数，是否保留是商业决策，
  不是规范决策——但应当写明：**认证是标准的一个可选副产品，不是标准存在的理由。**

## 一句话

> 影核的论点是「软件只有一个核，你看到的都是影子」。
> 这句话在 `SPEC.md` 里一次都没出现过，而 `AP-2` 出现了 140 次。
> 先把那句话写进去，分数才知道自己是在为什么服务。
