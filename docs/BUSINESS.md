# Commercial Value and Neutrality

ActionParity should be an open standard and a commercial ecosystem.

Those goals reinforce each other when the standard remains freely implementable and businesses compete on adoption, evidence, operations, and support.

## Who pays

### Desktop application vendors

They pay to:

- reduce GUI test flakiness and release cost;
- expose capabilities safely to AI assistants;
- prevent GUI/CLI/API drift;
- pass enterprise automation and accessibility requirements;
- migrate legacy click-handler logic into a testable core.

### Enterprises

They pay to:

- audit which application actions agents can perform;
- enforce confirmation, scope, and least privilege;
- retain execution evidence;
- run conformance tests on approved software versions;
- integrate internal applications into agent platforms.

### AI platform vendors

They pay to:

- obtain dependable application tools instead of relying on Computer Use;
- compare model behavior against identical action surfaces;
- reduce token, latency, and failure costs;
- access certified application adapters.

### Testing and compliance organizations

They pay for:

- conformance test suites;
- device and operating-system labs;
- report management;
- training and accreditation;
- repeatable evidence formats.

## Product opportunities

### 1. ActionParity CI

A hosted dashboard that:

- validates manifests and schemas;
- discovers GUI and machine bindings;
- computes strict parity;
- stores test evidence;
- tracks regressions by release;
- produces public or private reports.

The local validator remains open. The paid product sells collaboration, scale, history, policy, and managed infrastructure.

### 2. Migration toolkit

Static and runtime analysis for:

- locating business logic inside GUI handlers;
- inventorying meaningful controls;
- discovering existing CLI/API/MCP equivalents;
- suggesting Action IDs and schemas;
- generating adapters and binding tests.

### 3. Enterprise policy plane

A commercial control plane can add:

- role and scope management;
- confirmation policies;
- secrets integration;
- audit retention;
- signed execution evidence;
- environment isolation;
- fleet conformance monitoring.

### 4. Certification and test labs

Offer independent AP-1 through AP-4 verification on clean Windows, macOS, and Linux machines.

Revenue can come from test execution and evidence review, not from selling exceptions to the standard.

### 5. Framework support

Commercially supported adapters and migration services for Electron, Tauri, .NET, Swift, Python, and enterprise legacy stacks.

### 6. Industry packs

Domain-specific profiles can add requirements for:

- finance;
- healthcare;
- industrial control;
- document software;
- developer tools;
- AI model evaluation.

Profiles should extend, not fork, the core standard.

### 7. Training

Developer, architect, QA, and auditor curricula:

- Action Core design;
- agent-safe CLI design;
- semantic GUI automation;
- parity testing;
- risk and rollback;
- conformance review.

## The moat

The standard text is not the moat.

Durable advantages may come from:

- the largest cross-framework conformance test corpus;
- trusted clean-machine test infrastructure;
- migration automation;
- enterprise integrations;
- certification reputation;
- historical reliability data;
- developer and framework partnerships;
- a registry of verified applications and adapters.

Keeping the specification open expands the market for those advantages.

## Neutrality safeguards

To remain credible:

1. The specification, schemas, validator, and reference test vectors stay open.
2. Self-attestation remains free.
3. Normative changes happen in public.
4. Commercial customers cannot buy weaker requirements.
5. Certification identifies the exact application and standard version.
6. Certification rules are published.
7. Trademark use is separated from implementation rights.
8. Governance expands beyond the founding company before v1.0.
9. Reference adapters use a permissive license.
10. No required dependency points exclusively to a paid service.

## Recommended organizational model

### Stage 1

Founder-led open-source project with public RFCs and transparent releases.

### Stage 2

A commercial company funds tooling, migration, cloud CI, and certification while a multi-party technical steering group controls the specification.

### Stage 3

Move normative governance and trademarks into a neutral foundation or dedicated nonprofit when there are enough independent implementers.

The company can continue selling products around the standard without owning private control of conformance semantics.

## First commercial proof

U-King is the ideal first proof because it produces both internal and public value:

- faster automated release testing;
- lower dependence on visual Computer Use;
- a reference Electron adapter;
- a migration case study;
- a credible AP-4 certification demonstration;
- a foundation for testing other Windows applications.

The first sellable offering should be:

> “We make your Windows application reliably operable and testable by both humans and AI, while preserving its existing GUI.”

That outcome is easier for customers to buy than an abstract protocol.
